## What each Do did

**Do 1 — Standup.** Appended the Day 4 entry to `docs/standup-w1.md`
(Yesterday / Today / Blocker), following the existing three-day pattern.

**Do 2 — Smallest change matching the ticket.** Practiced making the
smallest possible change in `workflows/lib/interpolate.ts`. First
reintroduced the exact ticket bug (`stringify()`'s `===` flipped to `!==`),
reverted it, then — at your request to not repeat the same bug — introduced
a different one-line bug in the same file: `getByPath()`'s guard changed
from `value === null || value === undefined` to
`value === null && value === undefined`. Since no value is ever both null
and undefined at once, that condition never fires, so a path that runs
through a null/undefined field throws instead of resolving to an empty
string. This is the bug still live at the end of Do 2 and Do 3.

**Do 3 — Checks.** Vitest was confirmed working (`npx vitest --version`,
then a sanity run of `graphvalidator.test.ts`), which needed `npm install`
first since `node_modules` was missing. Wrote
`workflows/tasks/run-workflow.test.ts` (a new test file — none existed for
`run-workflow.ts`), mocking `@trigger.dev/sdk`, `browserbase`,
`node-executors`, and `test-data-lib/data`, covering dependency-order
execution with placeholder interpolation, and a failed step stopping the
run. Also wrote `docs/hand-check-level2.md` with the manual verification
steps for the ticket plus the results of running `run-workflow.test.ts` and
`graphvalidator.test.ts`.

**Do 4 — The real fix.** Closes the Level 2 ticket: `getByPath()`'s guard
goes back to `value === null || value === undefined`, restoring the
short-circuit that makes a dead path resolve to an empty string instead of
throwing.

## Commit message (for the real fix commit)

```
fix: use || instead of && to stop a path walk on null or undefined

getByPath used && between the null check and the undefined check, so the
guard never triggered — a value equal to null was never also equal to
undefined, and the reduce kept indexing into it, throwing instead of
resolving the placeholder to an empty string.
```
